## 1. 产品概述

### 1.1 产品定位

PDFTwocast 是一款 **PDF 到双人播客的一键转换工具**。用户上传 PDF 文档，系统自动提取文本、生成自然对话脚本、合成双人语音，输出完整的播客音频文件。

### 1.2 目标用户

| 用户类型 | 场景 | 核心需求 |
|---------|------|---------|
| **内容创作者** | 将文章/报告快速转为播客 | 省去人工录音和后期，一键出片 |
| **教育从业者** | 教材/论文转音频课件 | 双人对话形式更易集中注意力 |
| **企业知识管理** | 内部文档转音频播报 | 通勤时"听"文档，提升效率 |
| **视障用户** | 获取 PDF 文档的内容 | 通过自然对话而非机械朗读获取信息 |

### 1.3 核心价值主张

- **零门槛**：上传 PDF 即得播客，无需写脚本、录音、后期
- **双人对话**：自然的主持人对话风格，不失"人味"，比单口朗读更具沉浸感
- **端到端**：AI 完成全部流程，用户只需点击「上传」和「播放」

## 2. 功能需求

### 2.1 功能架构

```
┌──────────────────────────────────────────────────┐
│                    PDFTwocast                     │
├──────────────┬──────────────────┬────────────────┤
│  输入层      │    处理层         │    输出层       │
├──────────────┼──────────────────┼────────────────┤
│ · PDF 上传   │ · 文本提取        │ · 对话脚本展示  │
│ · 语言选择   │ · 脚本生成        │ · 音频播放      │
│ · 引擎切换   │ · 语音合成        │ · 音频下载      │
│              │ · 多引擎降级      │                │
└──────────────┴──────────────────┴────────────────┘
```

### 2.2 功能详情

#### F-01 PDF 上传与文本提取

- **输入**：PDF 文件（任意编码、版式）
- **处理**：PyMuPDF 逐页提取纯文本，上限 8,000 字符
- **校验**：内容长度 ≥ 50 字符方可生成
- **输出**：纯文本字符串

#### F-02 播客脚本生成（降级模式）

- **触发条件**：播客大模型不可用或用户手动选择 DeepSeek 模式
- **LLM**：DeepSeek Chat API
- **角色设定**：
  - Alex（男）：资深行业观察者，沉稳专业
  - 小米（女）：好奇心旺盛的新人，轻松活泼
- **输出格式**：JSON 数组 `[{"speaker": "...", "text": "..."}]`
- **对话要求**：8-12 轮，有来有往，包含过渡语和首尾

#### F-03 播客大模型端到端生成（优先模式）

- **引擎**：火山引擎豆包语音播客大模型（SAMI Podcast TTS）
- **协议**：WebSocket 二进制协议（`volc.service_type.10050`）
- **能力**：输入文本 → 自动生成双人对话 → 一次合成带 BGM 的完整音频
- **音色**：自动分配男女声（`zh_female_mizaitongxue` / `zh_male_dayixiansheng`）
- **增强**：片头音乐 + 片尾音乐

#### F-04 语音合成（降级模式）

- **引擎**：MiniMax TTS（`speech-02-hd`）
- **分句合成**：每句对话独立请求 TTS，支持并发
- **音色映射**：
  | 角色 | 音色 ID |
  |------|--------|
  | Alex | male-qn-jingying |
  | 小米 | female-shaonv |
  | Sam  | male-qn-badao |
- **音频格式**：MP3, 32kHz, 128kbps, 单声道

#### F-05 音频合并

- 将多个分段 MP3 按顺序拼接为完整音频
- 字节级拼接（免重编码）

#### F-06 多引擎降级链

```
播客大模型 (优先)
    ↓ 失败
DeepSeek 脚本 + MiniMax TTS (降级)
    ↓ 失败
返回仅脚本（无音频）
```

- 引擎选择优先级：请求头 `X-TTS-Engine` > 播客大模型可用性 > MiniMax
- 失败自动降级，无感知切换

#### F-07 前端交互

- **页面**：响应式单页 Web 应用 (SPA)，663 行 HTML/CSS/JS
- **模式**：现代化卡片式设计，深紫 + 粉色主题
- **操作流程**：
  1. 拖拽/选择 PDF 文件
  2. 选择语言（中文/English）
  3. 点击「生成播客」→ 显示进度
  4. 展示对话脚本 + 音频播放器
  5. 下载 MP3 文件

#### F-08 健康检查

- `GET /health`：返回各引擎配置状态
- 前端据此判断默认引擎和可用性

## 3. 非功能需求

### 3.1 性能

| 指标 | 目标值 | 说明 |
|------|-------|------|
| PDF 文本提取 | ≤ 2 秒 | 8,000 字以内 |
| 播客大模型生成 | ≤ 120 秒 | 含 WebSocket 握手+音频流 |
| DeepSeek 脚本生成 | ≤ 60 秒 | API 调用 + JSON 解析 |
| MiniMax 单句 TTS | ≤ 30 秒/句 | 8-12 句并发 |
| 页面首屏加载 | ≤ 1 秒 | 纯静态 HTML |

### 3.2 可靠性

- LLM 调用失败时返回友好错误，不崩溃
- 单句 TTS 失败不阻断整体流程（50% 成功率即视为可用）
- WebSocket 连接失败自动降级

### 3.3 安全性

- API 密钥支持三种注入方式：环境变量 > 请求头 > 硬编码
- CORS 白名单控制（当前 `*` 全放通，生产需收紧）
- 上传文件大小限制由 FastAPI 默认控制

### 3.4 可维护性

- 核心逻辑集中在单一 `main.py`（约 524 行）
- WebSocket 协议独立封装为 `protocols.py`
- 前端内联在 `static/index.html`，零构建依赖

## 4. 用户流程

### 4.1 主流程（播客大模型模式）

```
用户打开页面 → 选择/拖入 PDF → 点击「生成播客」
  → 后端提取文本 → WebSocket 连接火山引擎
  → 播客大模型生成对话+音频
  → 前端展示脚本 + 播放音频
  → 用户可下载 MP3
```

### 4.2 降级流程

```
用户打开页面 → 选择 PDF → 点击生成
  → 播客大模型连接失败
  → 自动切换 DeepSeek 生成脚本
  → MiniMax 逐句合成
  → 合并为完整 MP3
  → 前端展示结果
```
